1. ESKI LIMIT DAVRANISI
==================================================

Eski fillGaps() uygulamasinda:

  const maxCandidates = 24000;

limiti, ayni fillGaps() cagrisi icindeki phase 0, phase 1, phase 2 ve
phase 3 icin ortak global aday limitiydi.

Adaylar phase sirasiyla tek candidates listesine ekleniyordu. Toplam liste
24.000'e ulastiginda su akista tum ust donguler kiriliyordu:

- col dongusu kiriliyordu.
- row dongusu kiriliyordu.
- phase dongusu kiriliyordu.

Sonuc olarak sonraki phase'lerin adaylari hic uretilmeden tarama sona
eriyordu.

600x600 SS2 tam alanda ham phase adaylari yaklasik olarak:

- Phase 0: 11.600
- Phase 1: 11.500
- Phase 2: 11.500
- Phase 3: 11.500
- Toplam: 46.100

Eski global limit nedeniyle phase 2 kismen, phase 3 ise tamamen
atlanabiliyordu.

==================================================
2. YENI LIMIT DAVRANISI
==================================================

Toplam aday butcesi korunmustur:

  maxCandidates = 24000

Ancak yeni olarak phase sayisina gore bagimsiz butce hesaplanir:

  phaseCandidateBudget = ceil(maxCandidates / phases.length)

Dort phase icin:

  phaseCandidateBudget = ceil(24000 / 4) = 6000

Her phase kendi sayacini kullanir:

  let phaseCandidateCount = 0;

Bir phase kendi 6.000 aday butcesine ulasinca yalnizca o phase'in col ve
row donguleri kirilir. Phase ana dongusu devam eder ve sonraki phase'e
gecilir.

Yeni davranista artik:

- Toplam aday sayisi kontrolsuz buyumez.
- Bir phase diger phase'lerin butcesini tuketemez.
- Phase 0, 1, 2 ve 3'ün hepsi aday uretme sansina sahiptir.
- Adaylar tum phase'lerden toplandiktan sonra mevcut score siralamasi
  korunur.
